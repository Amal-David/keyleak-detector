## Findings addressed

- **Advisory-matched Poetry transitive:** `tldextract` resolved `filelock` 3.29.6,
  which matched nine current filesystem/link-handling advisories. KeyLeak does
  not directly call filelock and exploitability was not demonstrated, but the
  affected package was present in the install graph. The lock now selects 4.2.4;
  its PyPI identity, Python compatibility, provenance metadata, and artifact
  hashes were independently checked.
- **Advisory-matched evaluation dependency:** the local REA/Ghidra evaluation
  resolved `zod` 4.4.3, affected by GHSA-mrhx-c7xc-m3w5 memory exhaustion. This is
  development-only and no production exposure was shown. An exact npm override
  now selects signed release 4.6.7 with the registry integrity value retained.
- **Trust-store follow-up:** direct `certifi` pins now select 2026.10.23 in both
  project metadata, the Poetry lock, root requirements, and the PHP deployment.
  The upstream diff removes emSign Root CA-C1 and emSign ECC Root CA-C3 and was
  checked against Mozilla/NSS distrust evidence and PyPI Trusted Publishing
  provenance. The incident scanner's published minimum remains 2026.10.19.
- **Subfinder security maintenance:** Docker and the explicitly consented Go
  installer now select upstream v2.17.0, whose release notes identify high-CVE
  dependency fixes plus bounded retry/body-handling fixes. Docker no longer
  trusts checksum files downloaded beside the artifacts; reviewed amd64/arm64
  hashes are pinned for Subfinder and the retained Amass 5.0.1 release.
- **Self-audit correctness:** the CODEOWNERS check treated the valid global rule
  `* @Amal-David` as incomplete because it searched for literal path names. It
  now recognizes global or explicit owned rules while ignoring comments and
  ownerless patterns. Focused regressions cover both cases.
- **Portable certificate regression:** the negative incident-root test assumed
  the first platform CA was unrelated. It now selects a non-incident certificate
  by fingerprint from the pinned certifi bundle, avoiding platform-order failures.

## Dependency and supply-chain review

All 28 Poetry lock entries and 142 npm dependency entries were compared with
official registry metadata and queried against OSV. Initial matches were the
nine filelock advisories and one Zod advisory described above; the 170-entry
post-fix batch had no match. All Poetry artifact hashes and npm integrity values
matched registry metadata; no selected Python release was yanked, and registry
metadata declared no npm install lifecycle hook. `npm audit` reported zero known
vulnerabilities; 137 installed packages had registry signatures and 27 had
provenance attestations. These are point-in-time metadata checks, not proof of
upstream implementation safety. The exact versions, advisory IDs, integrity
values, and lock hashes are in the
[dependency snapshot](2026-10-30-dependencies.json).

Amass 5.1.3 was reviewed but not selected: the 5.0.1-to-5.1.3 range contains 321
commits and substantial engine/API changes, and the release commits are unsigned.
No advisory requiring that upgrade was found, so compatibility review is deferred
rather than silently taking a broad upgrade.

## Remaining boundaries

- No third-party service, leaked credential, public target, or live certificate
  chain was tested. Synthetic scanner fixtures are not exposed credentials.
- Archive inputs were reviewed for snapshot limits, traversal, links, special
  files, nested budgets, and non-execution. Static review and fixtures do not
  establish safety for every parser input.
- Network paths were reviewed for redirect credential stripping, connection-time
  SSRF checks, authorization/attestation gates, bounded active probes, and output
  redaction. Production DNS, proxy, provider, and browser behavior was not tested.
- The Docker base image still uses a mutable upstream tag, and pip-based Docker
  installation does not hash-pin every transitive artifact. Those are known
  supply-chain gaps; the executable tool artifacts changed here are hash-pinned.
- Static review, registry/advisory queries, package audits, and CI are
  point-in-time evidence, not an exhaustive proof that the repository or its
  dependencies are secure.
