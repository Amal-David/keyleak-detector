## Findings addressed

- **Incomplete eMudhra package coverage:** the incident scanner implemented five
  of the six minimum package versions in the cited Python packaging guidance but
  omitted conda 26.9.4. The table, documentation, and a focused below/at-floor
  regression now cover conda. This remains version evidence, not a live trust-store
  or certificate-chain test.
- **Advisory-matched development dependencies:** the local synthetic REA/Ghidra
  evaluation locked MCP client 2.2.0 and server 2.0.0. Current upstream advisories
  affect their HTTP redirect/header handling, HTTP server input bounds, shared
  server routing, and authorization audience validation. Narrow npm overrides now
  select client/server/core 2.3.0, the upstream fixed release, while retaining
  `rea-agents` 3.1.0. KeyLeak's evaluation is local and stdio-oriented; reachability
  of the affected HTTP paths was not demonstrated, so this is dependency hygiene
  rather than a claim that KeyLeak exposed credentials or an HTTP service.

## Dependency and supply-chain review

All 28 Poetry lock entries, all 143 npm lock entries, and the deployment-only
Gunicorn pin were checked against official registry metadata and OSV/GitHub
advisories. Artifact hashes or npm integrity fields matched; no selected release
was yanked or deprecated, and no install lifecycle script was declared in the
selected metadata. No Python advisory matched the selected graph. Four MCP
advisories matched before the fix; none matched after it. The complete npm lock
diff changes only MCP client/server/core to 2.3.0 and updates their declared
license/dependency metadata. [Dependency snapshot](2026-10-23-dependencies.json)
records exact lock hashes and advisory IDs.

`npm ci --ignore-scripts` succeeded. Post-fix `npm audit` reported zero known
vulnerabilities; registry signature verification covered 137 installed packages
and provenance attestations covered 27. This is not an attestation claim for every
locked artifact or a guarantee of upstream behavior. Direct Python pins and the
Poetry lock were already current for the reviewed stable compatible releases, so
no speculative or breaking Python bump was made.

## Remaining boundaries

- No third-party service, leaked credential, public target, or live certificate
  chain was tested. Synthetic scanner fixtures are not exposed credentials.
- The incident scanner still covers only selected root manifests, not nested
  projects, installed environments, container layers, or every package manager.
- The public PHP checker is banner evidence. Its address pinning, redirect refusal,
  authorization acknowledgement, rate/concurrency limits, body cap, CORS policy,
  log handling, and redaction were reviewed, but no exploit request was sent.
- DNS prechecks elsewhere remain weaker than connection-time IP pinning; real
  mitmproxy/recon integrations and production-provider isolation were not exercised.
- Static review, registry queries, package audits, and CI are point-in-time evidence,
  not exhaustive proof that the repository or its dependencies are secure.
