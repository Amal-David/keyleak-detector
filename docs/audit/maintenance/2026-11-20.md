## Security review

The review covered credential handling and report redaction; SSRF, redirects,
cookies, authorization headers, and browser egress; authorization and active
probe gates; archive/path/symlink handling; injection, unsafe deserialization,
and subprocess boundaries; extension/native-host messages; database catalog
queries and generated SQL; GitHub Actions permissions and immutable action
references; `action.yml`; Docker/build/release paths; install hooks; and focused
regression coverage. Synthetic scanner fixtures were treated as test data, not
exposed credentials.

The database audit remains read-only: it validates catalog shapes, quotes
identifiers, bounds JSON, refuses non-regular and symlinked inputs, and emits SQL
for human review rather than applying grants or policy changes. Browser
credentials remain exact-origin scoped and are stripped after a cross-origin
redirect; every hop is re-guarded, native WebSockets use the same deny policy,
responses are size/deadline bounded, and probe evidence excludes returned row
values. Public-by-design labels require provider-specific evidence rather than
generic proximity alone. No credential exfiltration path, write-capable default
probe, injection path, unsafe deserialization, redirect credential-forwarding,
or archive escape was established.
